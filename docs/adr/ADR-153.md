# ADR-153: Granular Hierarchy Navigation Control

- **Issue:** [#153](https://github.com/jasonmotylinski/hierarchical-backlinks/issues/153)
- **Status:** Accepted
- **Date:** 2026-09-11
- **Author:** AE-SAY-WAY (reporter), jasonmotylinski

## Context

When `hideFolderNote` is enabled, folder notes are merged into their parent folder row in the hierarchy. The current click handler (`treeNodeView.ts:93-110`) behaves as follows:

| Row type | Click action |
|----------|-------------|
| Merged folder note row | `navigateTo()` — opens the folder note |
| Leaf node row | `navigateTo()` — opens the note |
| Plain folder row | `toggle()` — expand/collapse |

This means **there is no way to expand/collapse a folder that has a merged folder note** without clicking the small triangle icon. The entire row opens the note instead of toggling the folder.

This has been a persistent pain point for user AE-SAY-WAY, who filed 15+ issues (#120, #122, #126, #144, #153, #154, #155, #167, #168) related to folder note click/navigation behavior.

## Decision

Add a user setting to control folder note row click behavior:

1. **`openNoteOnRowClick`** (boolean, default: `true`)
   - `true`: Current behavior — clicking the row opens the folder note
   - `false`: Clicking the row toggles expand/collapse; modifier key opens the note

2. **`folderNoteOpenKey`** (enum, shown only when `openNoteOnRowClick` is `false`)
   - Options: `Alt`, `Ctrl`, `Shift`, `Meta`
   - Default: `Alt`
   - When the row is clicked with this modifier held, the folder note opens instead of toggling

This setting **only affects folder note rows**. Result rows (leaves) and plain folder rows are unchanged.

## Consequences

- Users who prefer the current behavior are unaffected (default preserves it)
- Users who want expand/collapse on folder note rows can opt in
- The existing test `treeNodeViewClick.spec.ts:116` ("navigates on whole-row click of a merged folder-note row") will need a companion test for the new behavior
- The click handler needs to check `e.altKey` / `e.ctrlKey` / `e.shiftKey` / `e.metaKey` based on the setting
- Settings UI needs a conditional second dropdown that appears when `openNoteOnRowClick` is unchecked

## Implementation

- **Types:** `src/types.ts` — added `openNoteOnRowClick` (boolean) and `folderNoteOpenKey` (string) to `HierarchicalBacklinksSettings`, plus `FOLDER_NOTE_OPEN_KEY_OPTIONS` const
- **Defaults:** `src/main/settings.ts` — `openNoteOnRowClick: true`, `folderNoteOpenKey: "alt"`
- **Settings UI:** `src/main/settings.ts` — toggle + conditional dropdown in "Folder notes" section
- **Click handler:** `src/tree/treeNodeView.ts` — `hasModifierKey()` helper; both `treeItemSelf` and `treeItemInner` click handlers check setting before navigating
- **Tests:** `src/tree/__tests__/treeNodeViewClick.spec.ts` — 8 new tests covering toggle, modifier navigation, wrong modifier, text click, default behavior, plain folders, and leaves
